# 演示脚本

本文档提供一条标准演示路径，用于说明 FactoryOffice-Agent 如何完成制造业企业知识库与办公流程闭环。项目事实以 [`../00_project_truth/PROJECT_SSOT.md`](../00_project_truth/PROJECT_SSOT.md) 为准。

## 1. 演示目标

演示重点不是展示普通聊天，而是展示：

- 企业知识库问答
- 文档引用来源
- Agent SOP、任务状态和 Trace
- 会议纪要转任务
- 设备异常转维修工单
- 质量异常处理工单
- 采购申请草稿
- 人工审批
- 审计日志

## 2. 准备工作

启动服务：

```bash
cp .env.example .env
docker compose up -d
```

访问地址：

```text
前端：http://localhost:3000
后端：http://localhost:8000
接口文档：http://localhost:8000/docs
```

演示文档位于：

```text
data/demo_docs/
```

初始化业务数据位于：

```text
data/seed/
```

## 3. 演示路径

### 步骤一：打开首页仪表盘

展示内容：

- 文档数量
- 任务数量
- 工单数量
- 待审批数量
- 最近审计记录

说明要点：

```text
系统不是单纯问答页面，而是知识库、流程对象、审批和审计的统一入口。
```

### 步骤二：知识库问答

问题一：

```text
采购金额超过 5 万需要谁审批？
```

预期说明：

- 系统检索《采购管理制度》。
- 回答采购审批要求。
- 返回引用来源。

问题二：

```text
临时焊接支架可以不走动火审批吗？
```

预期说明：

- 系统检索《安全生产规范》。
- 回答不能跳过动火审批。
- 提醒落实审批、清理可燃物、配置灭火器材和现场监护。

### 步骤三：设备异常生成工单草稿

输入：

```text
A3 产线空压机 E07 报警，末端压力波动，产线暂停 35 分钟。
```

预期输出：

- 工单类型：设备维修
- 优先级：紧急
- 故障描述：E07 压力传感器异常
- 建议检查：压力传感器接线、机械压力表读数、过滤器压差
- 需要人工确认：是

说明要点：

```text
系统不会直接提交正式工单，而是生成草稿，并在正式写入前进入审批。
```

### 步骤四：质量异常生成处理工单草稿

输入：

```text
B2 批次零件抽检发现 3 件尺寸超差，影响当前批次出货，请生成质量异常单。
```

预期输出：

- 工单类型：质量异常
- 异常类型：尺寸超差
- 影响范围：B2 批次
- 初步处置建议：隔离批次、暂停放行、复检关键尺寸
- 需要人工确认：是

说明要点：

```text
系统只生成 NCR/质量异常工单草稿，不直接判定最终责任，不直接决定放行、返工或报废。
```

### 步骤五：采购需求生成申请草稿

输入：

```text
申请采购 4 个空压机过滤器滤芯，用于 A3 产线空压机稳定性改善，预算 2800 元，供应商为苏州恒压机电设备有限公司。
```

预期输出：

- 物品名称
- 数量
- 用途
- 预算
- 供应商
- 是否需要审批

说明要点：

```text
采购申请属于正式业务动作，系统只生成草稿，提交前需要人工确认。
```

### 步骤六：会议纪要转任务

输入：

```text
会议时间：2026-01-09 16:00
会议主题：A3 产线空压机异常复盘
1. 张丽 1 月 12 日前确认滤芯交期。
2. 赵磊下周更新空压机点检表。
3. 李强 1 月 17 日前完成滤芯更换和试运行。
4. 如果滤芯交期晚于 1 月 15 日，需要升级生产经理确认临时方案。
```

预期输出：

- 任务列表草稿
- 负责人
- 截止日期
- 优先级
- 需要人工确认的字段

说明要点：

```text
会议纪要里的自然语言会被转成结构化任务，批量创建前仍需要确认。
```

### 步骤七：AI 助手中的 SOP 和 Trace

输入：

```text
帮我申请采购20个温度传感器，用于产线设备改造。
```

预期输出：

- 识别意图：采购申请
- 命中 SOP：采购申请 SOP
- 当前状态：collecting_info
- 缺失字段：预算、供应商
- 下一步追问：请补充预算金额和供应商
- Agent Trace：意图识别、SOP 匹配、补槽、工具选择、最终回答

说明要点：

```text
Agent 不是黑箱聊天窗口，而是有状态、有 SOP、有缺字段追问、有执行轨迹的业务调度器。
```

### 步骤八：项目周报草稿

输入：

```text
本周完成 A3 产线空压机 E07 报警排查，确认压力传感器接线松动。
过滤器压差接近上限，滤芯采购申请已提交但交期未确认。
下周计划完成滤芯更换、试运行和点检表更新。
```

预期输出：

- 本周完成事项
- 未完成事项与原因
- 下周计划
- 风险与问题
- 待决策事项

说明要点：

```text
周报是草稿，需要项目负责人审核，不能替代正式审批和质量记录。
```

### 步骤九：审批

进入审批页面，查看待审批动作：

- 采购申请待审批
- 维修工单待确认
- 批量任务待确认

操作：

```text
批准一条工单或任务审批
拒绝一条删除文档审批
```

预期说明：

- 批准后执行对应工具。
- 拒绝后不会执行业务动作。
- 审批意见会保留。

### 步骤十：审计日志

进入审计日志页面，查看：

- 用户输入
- 检索来源
- 工具名称
- 工具参数
- 执行状态
- 输出结果

说明要点：

```text
企业流程不仅要方便，还要能追踪、复盘和审计。
```

## 4. 推荐演示话术

```text
这个系统不是普通聊天机器人。它先查企业知识库，再生成结构化业务草稿。
凡是会影响任务、工单、采购、文档删除或安全质量风险的动作，都不会由 AI 直接执行，而是进入人工确认。
确认后再写入业务表，并记录审计日志。
```

## 5. 演示注意事项

- 不使用真实企业内部资料。
- 不演示 AI 直接执行高风险动作。
- 涉及安全、质量、采购、客户交付的问题，强调人工确认和责任边界。
- 当前项目是工程样板和 PoC 原型，不宣称替代生产级 OA、ERP、MES 或质量管理系统。
