# 后续计划

本文档说明 FactoryOffice-Agent 的迭代方向。项目事实以 [`../00_project_truth/PROJECT_SSOT.md`](../00_project_truth/PROJECT_SSOT.md) 为准。

## 1. 迭代原则

项目按“先闭环，再增强”的方式推进。

优先级：

1. 先保证本地能跑通。
2. 再保证知识库问答有来源。
3. 再保证流程草稿能审批后落库。
4. 再增强 Agent 编排和评测。
5. 最后考虑外部系统集成。

## 2. 工程基础完善

目标：

- 后端、前端、数据库可以稳定启动。
- 环境变量、Docker、README 清晰可用。
- 初始化数据可以导入。
- 健康检查和基础页面正常。

计划事项：

- 完善 `scripts/init_db.py`
- 完善 `scripts/seed_demo_data.py`
- 完善 `scripts/ingest_demo_docs.py`
- 补充 Docker Compose 启动验证
- 补充后端单元测试和前端构建检查

## 3. 知识库能力完善

目标：

- 文档上传后能完成解析、切块、向量化和检索。
- 用户提问后能返回带引用来源的回答。

计划事项：

- 接入 Markdown、TXT、DOCX、PDF 解析
- 完善中文切块策略
- 接入 embedding 模型
- 使用 pgvector 存储向量
- 实现 `knowledge/search`
- 实现 `knowledge/ask`
- 增加引用来源展示
- 增加 RAG 测试问题集

## 4. 办公流程完善

目标：

- 会议纪要、设备异常、采购需求、项目记录都能生成结构化草稿。
- 草稿进入审批后可以写入业务表。

计划事项：

- 完善会议纪要任务抽取
- 完善设备异常优先级判断
- 完善采购申请缺字段追问
- 完善项目周报生成模板
- 审批通过后写入 tasks、tickets、purchase_requests
- 审批拒绝保留原因
- 工具执行写入 audit_logs

## 5. Agent 编排增强

目标：

- Agent 能更准确判断任务类型。
- 高风险动作能稳定进入人工确认。
- LangGraph 状态流转更清晰。

计划事项：

- 完善意图识别节点
- 完善知识检索节点
- 完善工具选择节点
- 完善审批判断节点
- 增加降级流程测试
- 增加 Agent 执行轨迹记录
- 增加错误恢复和提示

## 6. 前端页面完善

目标：

- 前端能清晰展示知识库、任务、工单、采购、审批和日志。
- 页面简洁稳定，适合企业内部系统风格。

计划事项：

- 首页仪表盘接入真实统计数据
- 知识库页面支持上传、列表、切块查看
- AI 助手页面展示回答、来源和工具调用预览
- 工作流页面支持四类流程输入
- 任务、工单、采购页面接入列表和详情
- 审批页面支持批准、拒绝和查看执行结果
- 审计日志页面支持筛选和详情查看

## 7. 评测与质量保障

目标：

- 不只验证接口能跑，还要验证回答和流程是否符合企业常识。

计划事项：

- 增加文档解析测试
- 增加知识库检索测试
- 增加引用来源测试
- 增加会议纪要转任务测试
- 增加维修工单生成测试
- 增加采购申请缺字段测试
- 增加审批通过和拒绝测试
- 增加安全高风险场景测试

## 8. 后续扩展方向

在核心闭环稳定后，可以考虑：

- 接入企业真实身份认证
- 增加更细的角色权限
- 接入对象存储
- 增加 Redis 或任务队列
- 接入真实 OA、ERP、MES 或协同平台
- 增加更多制造业文档类型
- 增加工单 SLA 和超时提醒
- 增加供应商质量跟踪
- 增加项目风险看板

## 9. 不优先做的事项

当前不优先做：

- 多租户 SaaS
- 大模型训练或微调
- 复杂组织权限体系
- 真实企业敏感数据处理
- 绕过人工确认的自动执行
- 医疗、金融、法律等高风险专业场景

## 10. 成熟度目标

项目逐步达到以下状态：

```text
能启动
  ↓
能导入文档
  ↓
能基于文档回答
  ↓
能生成流程草稿
  ↓
能人工审批
  ↓
能执行工具并落库
  ↓
能审计追踪
  ↓
能通过测试和演示稳定复现
```
