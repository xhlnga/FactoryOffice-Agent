# 后续计划

本文档说明 FactoryOffice-Agent 的迭代方向。项目事实以 [`../00_project_truth/PROJECT_SSOT.md`](../00_project_truth/PROJECT_SSOT.md) 为准。

## 1. 迭代原则

项目按“先闭环，再增强”的方式推进。

当前优先级：

1. 先保证本地能跑通。
2. 再保证知识库问答有来源。
3. 再保证流程草稿能审批后落库。
4. 再增强 Agent 编排、SOP、补槽、Trace 和评测。
5. 最后考虑外部系统集成。

## 2. 工程基础完善

目标：

- 后端、前端、数据库可以稳定启动。
- 环境变量、Docker、README 清晰可用。
- 初始化数据可以导入。
- 健康检查和基础页面正常。

当前已具备：

- `scripts/seed_demo_data.py`
- `scripts/ingest_demo_docs.py`
- Docker Compose 启动后端、前端和 PostgreSQL/pgvector
- 后端单元测试
- 前端类型检查和构建检查

后续可增强：

- 增加更细的启动健康检查脚本
- 增加 CI 自动测试

## 3. 知识库能力完善

目标：

- 文档上传后能完成解析、切块、向量化和检索。
- 用户提问后能返回带引用来源的回答。

当前已具备：

- Markdown、TXT、DOCX、PDF 解析
- 中文切块策略
- OpenAI-compatible embedding 配置入口
- 无 API Key 场景下的本地演示向量
- pgvector 存储和检索
- `knowledge/search`
- `knowledge/ask`
- 引用来源展示
- RAG 测试用例

后续可增强：

- 增加混合检索和更细粒度权限过滤
- 增加生产级 Embedding 批量调用和失败重试

## 4. 办公流程完善

目标：

- 会议纪要、设备异常、采购需求、项目记录都能生成结构化草稿。
- 草稿进入审批后可以写入业务表。

当前已具备：

- 会议纪要任务抽取
- 设备异常优先级判断
- 质量异常工单草稿
- 采购申请缺字段追问
- 项目周报生成模板
- 审批通过后写入 tasks、tickets、purchase_requests
- 审批拒绝保留原因
- 工具执行写入 audit_logs

后续可增强：

- 把审批流从固定规则升级为可配置多级审批
- 增加工单 SLA、超时提醒和责任部门配置

## 5. Agent 编排增强

目标：

- Agent 能更准确判断任务类型。
- Agent 能匹配 SOP 并维护任务状态。
- Agent 能发现缺失字段并支持多轮补槽。
- 高风险动作能稳定进入人工确认。
- LangGraph 状态流转更清晰。

当前已具备：

- 意图识别节点
- SOP 匹配
- 任务状态机
- 缺字段补槽
- 知识检索节点
- 工具选择节点
- 审批判断节点
- LangGraph 和本地降级流程
- Agent Trace
- 降级流程测试

后续可增强：

- 增加 Agent 会话持久化表
- 增加更细的错误恢复和补偿提示

## 6. 前端页面完善

目标：

- 前端能清晰展示知识库、任务、工单、采购、审批和日志。
- 页面简洁稳定，适合企业内部系统风格。

当前已具备：

- 首页仪表盘接入真实统计数据
- 知识库页面支持上传、列表、问答和引用来源展示
- AI 助手页面展示回答、SOP、任务状态、缺失字段、工具调用预览和 Trace
- 工作流页面支持会议、维修、质量、采购和周报流程输入
- 任务、工单、采购页面接入列表和详情
- 审批页面支持批准、拒绝和查看执行结果
- 审计日志页面支持筛选和详情查看

后续可增强：

- 前端组件进一步拆分
- 增加更友好的多轮上下文操作体验

## 7. 评测与质量保障

目标：

- 不只验证接口能跑，还要验证回答和流程是否符合企业常识。

当前已具备：

- 文档解析测试
- 知识库检索测试
- 引用来源测试
- 会议纪要转任务测试
- 维修工单生成测试
- 质量异常工作流测试
- 采购申请缺字段测试
- 审批通过和拒绝测试
- 权限和高风险场景测试
- Agent 路由、SOP 状态和多轮补槽测试

后续可增强：

- 增加端到端浏览器测试
- 增加接口压测和安全扫描

## 8. 后续扩展方向

在核心闭环稳定后，可以考虑：

- 接入企业真实身份认证
- 增加更细的角色权限
- 接入对象存储
- 增加 Redis 或任务队列
- 接入真实 OA、ERP、MES 或协同平台
- 增加更多制造业文档类型
- 增加工单 SLA 和超时提醒
- 增加供应商质量跟踪
- 增加项目风险看板

## 9. 不优先做的事项

当前不优先做：

- 多租户 SaaS
- 大模型训练或微调
- 复杂组织权限体系
- 真实企业敏感数据处理
- 绕过人工确认的自动执行
- 医疗、金融、法律等高风险专业场景

## 10. 成熟度目标

项目逐步达到以下状态：

```text
能启动
  ↓
能导入文档
  ↓
能基于文档回答
  ↓
能生成流程草稿
  ↓
能人工审批
  ↓
能执行工具并落库
  ↓
能审计追踪
  ↓
能通过测试和演示稳定复现
```
