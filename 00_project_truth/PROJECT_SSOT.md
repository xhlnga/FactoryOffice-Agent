# FactoryOffice-Agent 项目唯一真源

## 1. 项目名称

FactoryOffice-Agent

## 2. 中文定位

制造业企业知识库与办公流程智能体

## 3. 项目一句话说明

FactoryOffice-Agent 是一个面向制造业企业办公场景的 AI Agent 工程样板，围绕企业制度、SOP、设备手册、质量流程、安全规范和项目资料，提供知识库问答、流程草稿生成、人工审批、工具执行和审计追踪能力。

## 4. 项目核心判断

本项目不是通用聊天机器人，也不是只展示大模型问答能力的演示页面。

项目重点放在企业真实办公链路：

```text
员工提问 / 上传文件 / 输入业务描述
        ↓
系统判断任务类型
        ↓
检索企业知识库
        ↓
生成回答、任务、工单、采购申请或周报草稿
        ↓
涉及正式业务写入时进入人工确认
        ↓
人工批准后执行对应工具
        ↓
写入业务表和审计日志
```

这个流程更接近制造业企业真实使用 AI 的方式：先辅助查资料和生成草稿，再由授权人员确认，最后留下可追踪记录。

## 5. 当前工程真实能力

当前代码库已经包含以下可运行能力：

- FastAPI 后端服务和 `/api/health` 健康检查。
- Vue3 + Element Plus 前端页面。
- PostgreSQL + pgvector 数据库。
- Docker Compose 一键启动后端、前端和数据库。
- 文档上传、文件大小限制、文件哈希去重和上传目录管理。
- Markdown、TXT、PDF、DOCX 文档解析。
- 文档切块、向量化、pgvector 入库和相似度检索。
- 未配置真实 Embedding API 时，提供中文友好的本地演示向量兜底。
- 知识库检索和问答接口，回答返回引用来源。
- 会议纪要转任务草稿。
- 设备异常转维修工单草稿。
- 质量异常转 NCR/质量异常工单草稿。
- 采购需求转采购申请草稿，并检查必要字段。
- 项目记录转周报草稿。
- Agent 意图识别和 LangGraph 编排，未安装 LangGraph 时有本地降级执行流程。
- 任务、工单、采购申请、审批和审计日志等业务表。
- 高风险动作先进入 approvals 表，批准后才写入正式业务表。
- 审批、审计日志、文档删除申请需要主管或管理员角色。
- 审批执行成功或失败都会写入可追踪结果。
- 演示文档、初始化业务数据、导入脚本、评测模块和后端测试。

## 6. 面向的企业场景

项目主要面向中国制造业、装备制造、工业设备、自动化设备、仪器仪表、汽车零部件、新能源设备等企业中的以下场景：

- 制度、流程、SOP、手册和项目资料较多，员工查找成本高。
- 采购、维修、质量、差旅、安全等流程依赖经验，容易漏字段或漏审批。
- 会议纪要、项目周报、异常报告等文本材料重复整理工作多。
- 设备异常和质量异常需要快速形成可确认、可追踪的处理草稿。
- 企业希望 AI 可以辅助办公，但不能绕过权限、审批和审计。

## 7. 目标使用角色

当前项目覆盖的典型角色包括：

- 普通员工：提问、上传文档、生成流程草稿。
- 设备人员：查询维修手册，生成维修工单草稿。
- 质量人员：根据异常描述生成质量异常处理草稿。
- 采购人员：整理采购申请草稿和必要字段。
- 项目负责人：整理会议任务和项目周报。
- 部门主管：审批任务、工单、采购申请和文档删除申请。
- 信息化或技术负责人：评估系统架构、接口边界、数据模型和可扩展性。

## 8. 当前功能边界

当前版本只承诺以下范围：

- 企业知识库文档上传、解析、切块、入库和检索。
- 基于知识库的问答和引用来源展示。
- 会议纪要、设备异常、质量异常、采购需求、项目记录等固定工作流。
- 任务、工单、采购申请等模拟业务系统。
- 人工审批和审计日志。
- 本地 Docker Compose 部署。
- OpenAI-compatible LLM 和 Embedding 配置入口。

当前版本不承诺以下内容：

- 不直接接入真实 ERP、MES、OA、飞书、钉钉、企业微信。
- 不处理真实企业涉密资料。
- 不做生产级多租户 SaaS。
- 不做完整企业权限体系，只提供本地角色模拟。
- 不替代安全、质量、财务、法务等责任岗位的最终判断。
- 不允许 Agent 绕过人工确认直接执行高风险动作。
- 不训练或微调大模型。

## 9. 为什么说项目高度拟真

项目拟真不是因为文档写得像企业，而是因为代码结构和业务机制尽量贴近真实企业系统。

### 9.1 有企业知识库，不只靠模型记忆

系统先解析和检索企业文档，再生成回答和引用来源。这样符合企业知识库场景对可追溯性的要求，避免让模型凭空回答制度、维修、安全或质量问题。

### 9.2 有业务对象，不只是聊天记录

系统有 users、documents、document_chunks、tasks、tickets、purchase_requests、approvals、audit_logs 等表。这些对象对应企业真实办公系统里的用户、文档、任务、工单、采购申请、审批和日志。

### 9.3 有人工确认，不让 AI 直接越权

创建任务、提交工单、提交采购申请、删除文档等动作不会直接写入正式业务表。系统先创建审批记录，人工批准后才执行工具。这符合企业对责任边界和流程控制的基本要求。

### 9.4 有审计日志，方便复盘和追责

系统记录用户输入、动作类型、工具参数、执行结果和状态。企业使用 AI 辅助办公时，审计日志是降低黑箱风险的重要机制。

### 9.5 有明确边界，便于后续对接

当前版本用数据库模拟业务系统，暂不直接接 ERP、MES、OA 或即时通讯平台。这样能先验证知识库、流程、审批、日志的闭环，再逐步扩展外部系统适配。

## 13. 当前开放的工作流

### 13.1 知识库问答

```text
用户提问
  ↓
问题向量化
  ↓
pgvector 检索相关文档切块
  ↓
构造 RAG Prompt
  ↓
调用 LLM 或使用本地抽取式兜底回答
  ↓
返回回答和引用来源
```

### 13.2 会议纪要转任务

```text
会议纪要
  ↓
提取任务、负责人、截止日期和优先级
  ↓
生成任务草稿
  ↓
写入待审批记录
  ↓
主管批准后创建任务
  ↓
写入审计日志
```

### 13.3 设备异常转维修工单

```text
设备异常描述
  ↓
识别设备、报警、停线和风险关键词
  ↓
生成维修工单草稿
  ↓
进入审批
  ↓
批准后创建维修工单
  ↓
写入审计日志
```

### 13.4 质量异常处理

```text
质量异常描述
  ↓
识别批次、异常类型、影响范围和处置建议
  ↓
生成 NCR/质量异常工单草稿
  ↓
进入质量负责人或授权人员确认
  ↓
批准后创建质量异常工单
  ↓
写入审计日志
```

系统只生成草稿和建议，不直接判定最终责任、放行、返工或报废。

### 13.5 采购申请

```text
采购需求
  ↓
提取物品名称、数量、用途、预算和供应商
  ↓
缺字段时提示补充
  ↓
字段完整后生成采购申请草稿
  ↓
进入审批
  ↓
批准后创建采购申请
  ↓
写入审计日志
```

### 13.6 项目周报

```text
项目记录
  ↓
提取进展、问题、质量风险、设备风险、采购风险和下周计划
  ↓
生成周报草稿
  ↓
项目负责人复核后使用
```

## 14. 权限与审批规则

当前版本使用请求头模拟角色：

```text
X-User-Role: manager
```

规则：

- 普通员工可以查询知识库、上传文档、生成流程草稿。
- 主管或管理员可以查看审批、批准审批、拒绝审批、查看审计日志、申请删除文档。
- 高风险动作先进入 approvals 表。
- 审批通过后才调用对应服务写入业务表。
- 执行成功或失败都记录执行结果。

该机制是本地演示级权限模型，正式生产环境需要替换为企业统一认证和权限系统。

## 15. 项目目录原则

```text
00_project_truth/ 是项目事实中心，当前只保留唯一真源文件。
backend/ 是后端业务能力。
frontend/ 是企业操作界面。
data/ 是演示文档、初始化数据和上传目录。
docs/ 是普通技术文档。
scripts/ 是可复现导入和评测工具。
README.md 是对外说明入口。
SUPERVISOR_COMPATIBILITY.md 是面向业务和管理人员的项目说明。
```

`00_project_truth/` 当前只包含：

```text
PROJECT_SSOT.md
```

## 16. 后续增强方向

后续增强必须在不破坏当前边界的前提下推进：

- 接入真实企业统一认证。
- 接入真实 OA、ERP、MES、飞书、钉钉或企业微信。
- 增加更细粒度的文档权限。
- 增加审批流配置和多级审批。
- 增加工单状态流转和任务状态变更审计。
- 增加文件对象存储和病毒扫描。
- 增加更完整的 RAG 评测集。
- 增加操作幂等、失败重试和补偿机制。
- 增加生产环境日志留存和脱敏策略。

## 17. 成功标准

项目被认为达到当前目标，应满足：

- Docker Compose 可以启动完整服务。
- 前端、后端、数据库可以连通。
- 演示文档可以导入知识库并生成切块。
- 知识库问题可以返回引用来源。
- 会议、维修、质量、采购、周报流程可以生成草稿。
- 创建任务、工单、采购申请等正式动作需要审批。
- 审批通过后可以写入业务表。
- 审计日志可以记录工具执行结果。
- 项目文档能清楚说明价值、边界和技术结构。
