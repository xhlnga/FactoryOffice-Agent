# 华东精工制造有限公司项目周报模板

**文件编号：** HDJG-PMO-006  
**版本号：** V1.0  
**生效日期：** 2026-01-01  
**归口部门：** 项目管理办公室（PMO）  
**适用范围：** 新产品导入、客户项目、工艺改善、设备改造、质量整改、信息化建设及跨部门专项项目  
**密级：** 内部公开  

---

## 1. 目的

为统一公司各类项目的周度汇报格式，提高项目进度、风险、问题、资源需求和跨部门协同事项的透明度，便于管理层及时掌握项目状态、识别延期风险、推动问题闭环，特制定本模板。

本模板用于项目经理、项目负责人或专项任务负责人编制项目周报，也可作为企业知识库与办公流程 Agent 从会议纪要、任务列表、邮件、工单和项目记录中自动生成周报的标准结构。

---

## 2. 适用项目类型

本模板适用于以下项目：

1. 新产品导入项目，包括样件试制、小批量试产、量产爬坡、客户 PPAP 或客户审核准备；
2. 客户质量问题整改项目，包括 8D 报告、批量返工、过程能力提升、客户投诉关闭；
3. 设备改造与维修专项，包括关键设备大修、空压系统改造、产线自动化升级、设备搬迁；
4. 工艺改善项目，包括节拍优化、良率提升、工装夹具优化、换型时间降低；
5. 供应链保障项目，包括供应商导入、关键物料替代、交期恢复、降本改善；
6. 安全环保整改项目，包括隐患整改、消防改善、危废管理、危险作业规范化；
7. 信息化建设项目，包括企业知识库、流程 Agent、MES/OA/ERP 接口、数据看板建设；
8. 其他由总经理、部门负责人或 PMO 指定需要周报跟踪的跨部门事项。

---

## 3. 周报提交要求

### 3.1 提交频次

项目周报原则上每周提交一次。常规项目应在每周五 18:00 前提交；涉及客户交付、停线风险、重大质量异常或安全隐患的项目，应根据项目负责人要求增加临时更新。

### 3.2 提交对象

周报提交对象一般包括：

1. 项目发起部门负责人；
2. 项目经理或专项负责人；
3. 相关协同部门负责人；
4. PMO；
5. 对项目结果承担决策责任的管理层。

若项目涉及客户、供应商或外协单位，外发版本应由项目负责人审核，避免泄露内部成本、人员、供应商评价、内部缺陷原因等敏感信息。

### 3.3 周报基本原则

1. 只写事实，不写空话；
2. 每个问题必须有责任人、下一步动作和计划完成时间；
3. 风险必须说明影响、概率、等级和应对措施；
4. 进度不得只写“推进中”“持续跟进”，必须写明完成内容或阻塞点；
5. 延期事项必须说明原因、影响和恢复计划；
6. 需要管理层决策的事项必须单独列出；
7. 周报中的数据口径应与项目计划、会议纪要、工单、质量记录和采购记录保持一致。

## 4. 项目状态分级

为便于管理层快速识别项目状态，公司采用绿、黄、红三色状态。

| 状态 | 含义 | 触发条件 | 处理要求 |
|---|---|---|---|
| 绿色 | 正常 | 本周关键任务按计划完成，暂无影响里程碑的风险 | 项目组按计划推进 |
| 黄色 | 预警 | 存在延期、资源不足、质量波动、供应风险或待决策事项，但仍可通过措施恢复 | 项目经理需提出纠偏措施并跟踪 |
| 红色 | 异常 | 已影响关键里程碑、客户交付、生产连续性、安全合规或预算控制 | 项目负责人必须升级管理层或 PMO |

### 4.1 绿色状态示例

1. 试制样件已完成，检测结果满足阶段目标；
2. 设备安装按计划完成，试运行未发现重大异常；
3. 采购物料按期到货，供应商文件齐全；
4. 本周关闭全部计划内问题，无新增重大风险。

### 4.2 黄色状态示例

1. 关键物料交期延后 3 天以内，但可通过调整生产计划缓冲；
2. 设备调试出现异常报警，已由设备部跟进，尚未影响总节点；
3. 客户样件反馈有轻微尺寸偏差，需要追加确认；
4. 部门资源冲突导致任务完成率低于 80%；
5. 风险尚未发生，但若下周不处理将影响里程碑。

### 4.3 红色状态示例

1. 客户交付节点已无法按原计划满足；
2. 关键设备故障导致项目试产停滞；
3. 重大质量异常未关闭，影响批量发运；
4. 安全隐患未整改且影响施工或试运行；
5. 预算超支超过批准预算的 10%；
6. 关键决策超过 5 个工作日未回复并影响后续执行。

## 6. 周报字段填写说明

### 6.1 项目目标

项目目标应具体、可验证，避免写成口号。推荐格式：

```text
为解决 {业务问题}，在 {时间} 前完成 {交付物}，达到 {量化指标或验收标准}。
```

示例：

```text
为降低 A3 产线空压机异常停机对生产节拍的影响，在 2026-02-15 前完成压力传感器排查、过滤器更换和报警策略优化，使空压机非计划停机次数较上月下降 50%。
```

### 6.2 本周完成事项

完成事项必须能被验证。以下表达不推荐：

```text
持续推进供应商沟通。
继续优化方案。
跟进质量问题。
```

推荐写法：

```text
完成 3 家供应商报价比价，形成《空压机压力传感器采购比价表》并提交采购审批。
完成 A3 产线 20 件样件复测，19 件合格，1 件尺寸偏差已转入质量异常流程。
完成空压机 E07 报警现场排查，确认压力传感器接线端子松动并完成紧固。
```

### 6.3 未完成事项

未完成事项必须说明真实原因，不得只写“客观原因”“资源问题”“待确认”。应尽量明确为以下类型之一：

1. 人员资源不足；
2. 供应商交付延期；
3. 设备故障或调试不稳定；
4. 技术方案未冻结；
5. 客户反馈未返回；
6. 采购审批未完成；
7. 质量验证未通过；
8. 安全措施未满足；
9. 管理层决策未完成；
10. 其他可说明的具体原因。

### 6.4 下周计划

下周计划应对应本周问题和项目里程碑，不能只写常规事务。每项计划应有明确输出物，例如：

1. 测试报告；
2. 会议纪要；
3. 工单关闭记录；
4. 采购申请单；
5. 风险评估表；
6. 客户确认邮件；
7. 质量异常关闭报告；
8. 设备试运行记录；
9. 培训签到表；
10. 上线验收记录。

## 7. 风险分类与升级规则

### 7.1 风险分类

| 风险类型 | 说明 | 常见触发信号 |
|---|---|---|
| 进度风险 | 任务或里程碑可能延期 | 关键任务逾期、前置条件未满足、审批未完成 |
| 质量风险 | 输出物可能不满足客户或内部质量要求 | 尺寸偏差、重复缺陷、返工增加、验证未通过 |
| 采购风险 | 物料、供应商、价格或合同影响项目 | 交期延迟、供应商变更、报价异常、单一来源 |
| 设备风险 | 设备故障、调试异常或产能不足 | 报警频繁、停机、备件缺失、维修未关闭 |
| 安全风险 | 可能造成人身伤害或合规问题 | 动火未审批、设备防护失效、叉车险肇、化学品泄漏 |
| 成本风险 | 预算超支或成本收益不达预期 | 预算使用率过高、返工成本增加、方案变更 |
| 人员风险 | 人员不足、职责不清或关键人不可用 | 责任人变更、跨部门无人承接、培训未完成 |
| 客户风险 | 客户反馈、审核或交付要求变化 | 客户投诉、审核不通过、需求变更 |

### 7.2 风险等级

| 等级 | 判断标准 | 周报处理要求 |
|---|---|---|
| 低 | 对项目影响有限，项目组可自行处理 | 列入风险表，责任人跟踪 |
| 中 | 可能影响阶段节点或需要跨部门支持 | 项目负责人协调，必要时提交 PMO |
| 高 | 已影响关键里程碑、交付、安全、质量或预算 | 必须升级管理层，并列入待决策事项 |

### 7.3 必须升级的情形

出现以下任一情况，周报状态原则上不得标记为绿色：

1. 关键里程碑延期超过 3 个工作日；
2. 客户交付日期存在无法满足的风险；
3. 高风险安全隐患未关闭；
4. 重大质量异常未完成原因分析和遏制措施；
5. 关键设备故障影响试制、试产或量产；
6. 预算超支超过 10% 或预计将超支；
7. 决策事项超过 5 个工作日未反馈；
8. 同一问题连续两周出现在周报中且无实质进展。

## 8. 任务清单标准字段

项目任务应使用统一字段，便于 Agent 从会议纪要、邮件和聊天记录中自动抽取。

| 字段 | 是否必填 | 说明 |
|---|---|---|
| task_id | 是 | 任务编号，例如 T-2026-001 |
| project_name | 是 | 项目名称 |
| task_title | 是 | 任务标题，建议 10-30 字 |
| task_description | 是 | 任务详细描述 |
| owner | 是 | 责任人 |
| owner_department | 是 | 责任部门 |
| collaborators | 否 | 协同人或协同部门 |
| due_date | 是 | 截止日期 |
| priority | 是 | 高 / 中 / 低 |
| status | 是 | 未开始 / 进行中 / 阻塞 / 已完成 / 已取消 |
| evidence | 否 | 输出物或证据链接 |
| risk_level | 否 | 低 / 中 / 高 |
| source | 否 | 来源会议、邮件、工单或记录 |

### 8.1 任务描述推荐格式

```text
{责任人} 需要在 {截止时间} 前完成 {具体动作}，输出 {可验证结果}，用于支持 {项目目标或下一步流程}。
```

示例：

```text
设备部李强需要在 2026-01-12 前完成 A3 产线空压机压力传感器复测，输出《空压机 E07 报警排查记录》，用于判断是否需要采购备件。
```

## 9. 会议纪要转周报规则

当 Agent 根据会议纪要自动生成周报时，应遵循以下规则。

### 9.1 信息抽取优先级

1. 明确写有“已完成”“已关闭”“已提交”“已验收”的内容，优先归入本周完成事项；
2. 明确写有“下周”“计划”“需要”“待完成”的内容，优先归入下周计划；
3. 明确写有“延期”“卡住”“无法”“缺料”“异常”“风险”“未关闭”的内容，优先归入风险与问题；
4. 明确写有“请某部门支持”“需要审批”“等待确认”的内容，优先归入跨部门协同事项或待管理层决策事项；
5. 明确写有日期和责任人的内容，应生成任务清单；
6. 没有责任人或截止时间的重要事项，应标记为“信息不完整，需要人工确认”。

### 9.2 不得自动编造的信息

Agent 不得自动编造以下内容：

1. 未在材料中出现的完成结论；
2. 未明确给出的测试数据、良率、金额、数量；
3. 未明确授权的责任人；
4. 未出现的客户反馈；
5. 未出现的审批结论；
6. 未出现的安全或质量关闭状态。

若信息缺失，应写为“未提供”或“需人工确认”。

### 9.3 自动生成状态判断

Agent 可基于以下规则初步判断项目状态：

1. 若材料中无延期、无高风险、无未决策事项，且本周关键任务完成，可标记为绿色；
2. 若存在延期但已提出恢复计划，或存在中等级别风险，可标记为黄色；
3. 若存在客户交付风险、重大质量异常、设备停机、安全隐患、预算严重超支或关键决策阻塞，应标记为红色；
4. 状态判断应说明依据，不得只输出颜色。

## 14. 常见问题

### 14.1 周报里可以只写“正常推进”吗？

不建议。周报必须写清楚本周完成了什么、下周要做什么、是否存在风险。单独写“正常推进”无法支持管理层判断，也无法让 Agent 抽取有效任务。

### 14.2 没有风险是不是可以不写风险表？

可以保留风险表并写“无新增风险”。如果项目连续两周没有任何风险，但关键任务也没有明显进展，项目负责人应说明原因。

### 14.3 责任人还没确定怎么办？

不能直接写“待定”后不处理。应在跨部门协同事项或待管理层决策事项中列出“需确认责任人”，并明确最晚确认时间。

### 14.4 项目延期了但是不影响最终交付，状态怎么填？

通常填黄色。周报中应说明延期原因、影响范围和恢复计划。若延期已经影响客户交付、生产计划、安全合规或预算，应标记为红色。

### 14.5 周报可以自动生成吗？

可以。Agent 可以根据会议纪要、任务清单、工单、采购记录、质量异常单等生成周报初稿，但项目负责人必须审核事实、数据、状态判断和外发内容。

## 15. 与其他制度的衔接

1. 涉及采购、供应商、报价、合同和付款的项目事项，应按《采购管理制度》执行；
2. 涉及员工外出、客户现场、供应商现场和项目差旅费用的事项，应按《差旅报销制度》执行；
3. 涉及设备故障、维修、空压机报警和备件更换的事项，应引用《设备维修手册_空压机》或设备部工单；
4. 涉及产品不合格、客户投诉、返工返修和 NCR 的事项，应按《质量异常处理流程》执行；
5. 涉及动火、高处、临时用电、叉车、消防、化学品和人员安全的事项，应按《安全生产规范》执行；
6. 周报不得替代正式审批、质量记录、维修记录或安全审批。周报只用于状态汇总和问题跟踪。

2. 各部门可在本模板基础上增加专项字段，但不得删除核心跟踪字段；
3. 本模板自 2026 年 1 月 1 日起执行；
4. 本模板用于开源演示项目时，所有项目名称、人员、指标和案例均为模拟内容，不代表真实企业信息；
5. Agent 自动生成周报时，应保留“需人工确认”标识，避免将不确定信息写成确定结论。
